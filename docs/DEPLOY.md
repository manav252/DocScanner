# Putting DocScanner online for a demo

Everything works without the backend (scanning, editing, OCR, export, backup
as a ZIP). So the simplest public demo is just the website + web app on
GitHub Pages. Add the backend only if you want to show account backup/sync.

Nothing in this repository deploys by itself, and no account is created for you.
The steps below are done by you, in your browser.

| Part | Where | Cost | Config in this repo |
|---|---|---|---|
| Website + web app | GitHub Pages | free | `.github/workflows/pages.yml` |
| Backend API (optional) | Render | free | `render.yaml` |
| Database | Neon Postgres | free | `DATABASE_URL` in Render |
| Page image storage | Cloudflare R2 | free (10 GB) | env vars in Render |

## 1. Website and web app on GitHub Pages (about 5 minutes)

The repository is already on GitHub: https://github.com/manav252/DocScanner

1. Open the repository on GitHub → **Settings** → **Pages**.
2. Under **Build and deployment** → **Source**, choose **GitHub Actions**.
3. Go to the **Actions** tab → **Deploy website and web app** → **Run workflow**
   (it also runs on every push to `main`). The first run takes about 5 minutes.
4. When it is green, open:
   - Website: **https://manav252.github.io/DocScanner/**
   - Web app: **https://manav252.github.io/DocScanner/app/**

Pages is served over HTTPS, so the camera works in phone browsers too. After the
first visit the app also works offline, and it can be installed ("Add to Home
Screen" on phones, the install icon in Chrome's address bar on computers).

Without step 2 below, the app's backup/sync screen simply reports that the server
cannot be reached; every other feature works.

## 2. Backend online: your checklist (about 20 minutes)

Accounts, backup and sync on the hosted site need the backend. You create three
free accounts and paste values into Render; nothing secret goes into the repo.
Free plans: Neon (Postgres, does not expire), Cloudflare R2 (10 GB), Render web
service (sleeps after 15 minutes idle; the app shows "Waking up the server…"
and waits instead of failing).

### ☐ 1. Neon (database)

1. Sign up at https://neon.tech → **Create project** (any name, region near you).
2. On the project dashboard click **Connect**. Turn **Connection pooling OFF**
   (the app needs the *direct* connection), then copy the connection string:
   `postgresql://…@ep-….neon.tech/neondb?sslmode=require…`
   → this is **`DATABASE_URL`**.

### ☐ 2. Cloudflare R2 (page images)

1. Sign up at https://dash.cloudflare.com → **R2 Object Storage** (free plan;
   Cloudflare may ask for a card to enable R2, the free tier is not charged).
2. **Create bucket** → name it **`docscanner`**.
3. **R2 → Manage API tokens → Create API token**: permission
   **Object Read & Write**, limited to the `docscanner` bucket → **Create**.
4. Copy from the result page (shown once):
   - **Access Key ID** → **`DOCSCANNER_S3_ACCESS_KEY`**
   - **Secret Access Key** → **`DOCSCANNER_S3_SECRET_KEY`**
   - the **S3 endpoint** `https://<account-id>.r2.cloudflarestorage.com`
     (without `/docscanner` at the end) → **`DOCSCANNER_S3_ENDPOINT`**

### ☐ 3. Render (the API)

1. Sign up at https://render.com with your GitHub account.
2. **New → Blueprint** → pick **manav252/DocScanner** → Render reads `render.yaml`.
3. It asks for the values marked secret. Paste:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Neon connection string (step 1) |
   | `DOCSCANNER_S3_ENDPOINT` | R2 endpoint (step 2) |
   | `DOCSCANNER_S3_ACCESS_KEY` | R2 Access Key ID |
   | `DOCSCANNER_S3_SECRET_KEY` | R2 Secret Access Key |

   Already set by the blueprint: `DOCSCANNER_JWT_SECRET` (generated by Render),
   `DOCSCANNER_CORS_ORIGINS` = `["https://manav252.github.io"]`, bucket
   `docscanner`, region `auto`, `DOCSCANNER_ENVIRONMENT=production`.
4. **Apply**. The first build takes ~5 minutes; database tables are created on start.
5. Open your service and copy its URL. If it is **not**
   `https://docscanner-api.onrender.com`: GitHub → repository **Settings → Secrets
   and variables → Actions → Variables → New repository variable** `API_URL` = your
   URL, then **Actions → Deploy website and web app → Run workflow**.
6. Check `https://<your-service>.onrender.com/health` shows
   `{"status":"ok","database":true,"storage":true}`.

### ☐ 4. Keep it awake for the demo

Pick one:
- **Uptime monitor** (recommended): free account at https://uptimerobot.com →
  **New monitor** → type HTTP(s), URL `https://<your-service>.onrender.com/health`,
  interval **every 10 minutes**. (Render free instances have 750 hours/month: enough
  for one service running all month.)
- **Or** open the site (or the `/health` URL) **2 minutes before** the demo.

Then tell me the service URL and I will check sign-up, upload, sync to a second
browser and download.

## Alternatives

- **Netlify / Vercel** instead of GitHub Pages: build command
  `cd app && flutter build web --release --base-href /app/ && cd .. && python3 tools/pwa_precache.py && mkdir -p public && cp -R website/. public/ && cp -R app/build/web public/app`,
  publish directory `public`. (Both need Flutter in the build image; GitHub Pages
  is simpler because the workflow installs it.)
- **Railway / Fly.io** instead of Render: deploy `backend/Dockerfile` with the
  repository root as build context, add a PostgreSQL database, and set the same
  `DOCSCANNER_*` variables as in `render.yaml`.

## Checklist before a demo

- [ ] Website opens; *How it works* finds the page in the sample photo.
- [ ] *Try it now* opens the app; the demo camera scans a page.
- [ ] On a phone: the real camera works (HTTPS), and the app installs from the browser.
- [ ] (With backend) `/health` is ok; sign up, scan, and the document appears on a second device.
